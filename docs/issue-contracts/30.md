# GitHub issue #30 — [Data/Location] Add nationwide Israeli store directory and coverage

- Source: https://github.com/eyal1990/super-market/issues/30
- State when synchronized: open
- Synchronized at: 2026-08-30T14:30:37.048Z

## Context

The product must support nearby-store selection across Israel without fabricating a nearby branch or making a provider-specific aggregator a required dependency. The current fixture has only a few branches, so the app needs a portable nationwide directory and a repeatable refresh path.

## Acceptance criteria

- Maintain a provider-neutral branch registry covering every supported chain and branch in the configured source dataset, with stable retailer/branch identity, chain, name, address, city, district, postal code when available, latitude/longitude, active status, source, and last-verified timestamp.
- Support full and incremental directory imports with validation, deterministic identity/deduplication, idempotent reruns, and malformed-row warnings. An empty or invalid refresh must not replace the last valid directory.
- Expose directory coverage/completeness metadata in the API and UI. Never present a fixture or partial source as a complete live inventory.
- Nearby search must return real branches ordered by distance and filtered by the requested shopping mode; it must not silently fall back to a distant or fake branch.
- Preserve privacy: arbitrary address lookup may use coordinates for proximity, but exact address text must not be persisted in browser storage or delivery handoff payloads.
- Include representative fixtures spanning Israel’s districts and automated tests for import, deduplication, coordinate validation, nearby ordering, mode filtering, and incomplete coverage messaging.
- Document the source matrix, refresh/runbook, limitations, and the path to replacing fixtures with a complete official source feed.

## Out of scope

Ordering, payment, retailer credentials, and claiming that a delivery handoff placed an order.
