## User problem
The current implementation can regress on the exact flows that make the site useful, especially first-run state and RTL interactions.

## Scope
Add automated browser/API coverage for the primary customer journeys and make it runnable from a fresh checkout.

## Acceptance criteria
- Tests cover first visit with empty basket and no selected store.
- Tests cover arbitrary-address search (mocked provider), branch selection, mode switching, product search, add/change/remove quantity, compare totals, stale/unavailable products, and delivery handoff/export.
- Mobile and desktop RTL smoke coverage exists.
- Tests are deterministic, fixture-backed, and do not require retailer credentials or a live geocoder.
- CI runs lint, typecheck, unit/API tests, build, and browser smoke tests with actionable failures.
- The README documents the exact commands.
