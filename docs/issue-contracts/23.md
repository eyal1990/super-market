# GitHub issue #23 — [UX] Make product discovery useful at catalog scale

- Source: https://github.com/eyal1990/super-market/issues/23
- State when synchronized: closed
- Synchronized at: 2026-08-30T18:52:04.913Z

## User problem
Even with a larger catalog, a single undifferentiated list will be difficult to shop.

## Scope
Improve product search and browsing for a real supermarket catalog.

## Acceptance criteria
- Search supports Hebrew/Latin names, brand, barcode, and common spelling/normalization variations.
- Results show loading, no-results, unavailable-in-selected-store, and stale-data states.
- Users can filter or browse by category and sort by relevance, price, and unit price where data permits.
- Search results are paginated or virtualized so a full catalog does not block the browser.
- Product cards expose enough context to choose correctly: pack size, unit, branch availability, price, freshness, and promotions.
- Search input, filters, and result counts remain usable in RTL on mobile.

## Dependencies
#20, #26, and legacy #9/#12.
