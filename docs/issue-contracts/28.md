# GitHub issue #28 — [UX] Build a first-time onboarding flow that gets a customer to a useful result

- State when synchronized: closed

## User problem
A new visitor currently lands on a dense dashboard with implicit defaults and no guided path to a meaningful comparison.

## Scope
Design and implement a short Hebrew/RTL onboarding sequence: address/location -> shopping mode -> nearby branches -> first product search.

## Acceptance criteria
- The first screen explains the value in one sentence and has one primary action.
- The flow shows progress and can be revisited without losing the basket.
- Empty, loading, error, ambiguous-address, and no-nearby-store states each have a recovery action.
- A user can reach a product price comparison in a small number of obvious steps on mobile.
- No fake location, store, basket, or product data is shown as if it were user-selected.
- Keyboard navigation, focus management, and screen-reader announcements are tested.
